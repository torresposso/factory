## Review rules

- Review the whole branch `{{.Branch}}` against {{.Base}} with the code-review skill: the standards, and
  whether it does what the spec asks.
- You did not write this branch. Run the checks yourself, and look at the page yourself when the
  change is visual, serving the preview on your `Preview port` instead of the port AGENTS.md names:
  `make preview PORT=<your port> DIR=tmp/preview-review`, in the background, and stop it with
  `make preview-stop DIR=tmp/preview-review`, never with `pkill`. The agent's own browser is not
  reachable from a card and cannot see the preview anyway; look with the tool that is there:

      chrome-devtools-axi run < tmp/look.js
      chrome-devtools-axi screenshot tmp/evidence/review-what.png
      chrome-devtools-axi stop

  `tmp/look.js` is a few lines of `await page.open("http://127.0.0.1:<your port>/...")`,
  `await page.fill("<css selector>", "...")`, `await page.click("<css selector>")` and
  `console.log(await page.eval(() => document.body.innerText))`, and `run` prints only what the script
  writes to stdout, so an `eval` without `console.log` prints nothing and a `return` is an error. Selectors work;
  a snapshot's `@refs` go stale the moment the page changes. Screenshot the viewport, not the whole
  page, and crop a long page to the part you care about.
- Save the screenshots you take in `tmp/evidence/` of your workspace (at most 3, PNG, named
  `review-what.png`). If a preview data directory you want already exists, use another name instead of
  removing it.
- Then look at the screenshot with `vision_analyze`, once and narrowly: pass `tmp/evidence/review-what.png` and one question
  about the one visual thing the spec asks for, not "describe the page". Do not look at the tickets' images
  in `tmp/evidence/`: they are for the pull request.
- Fix what it finds as new commits on the branch, then run `make verify` from the repo root. Do not
  rewrite history.
- Never push, never merge, never switch branches.
- Nobody is there to approve anything, and Hermes refuses whatever asks for approval. Never edit
  AGENTS.md, CLAUDE.md or any other agent-instruction file: name the change it needs in your summary.
  Keep each command one plain command: write a file with write_file and commit it with
  `git commit -F <file>` rather than wrapping it in `bash -c`, `sh -c`, `python -c` or a heredoc, and
  start anything long with `background=true` instead of a trailing `&`. A command that runs past five
  minutes in the foreground loses its container at five minutes and comes back as exit 137: put it in
  the background with its output in a file and read the file.
- Finish with kanban_complete: what you found and fixed, and metadata with verification (a list: each
  command you ran and its result), branch and commit. If you cannot fix a finding, call kanban_block with kind "needs_input" and it.
